# V1 验收矩阵

V1 定位为本地运行、人工介入、导出文件驱动，目标规模为 5 个微信小店。图表解析和 OCR 属于 V2，V1 只预留来源类型和解析产物 metadata。

## 功能范围

| 模块 | V1 验收标准 | V2 预留 |
|---|---|---|
| 店铺管理 | 可配置 5 个店铺，所有业务数据带 `shop_id` 和店铺名称快照 | 店铺分组、跨周期标签 |
| 原始文件归档 | 每个导出文件保存原始文件、来源页面、时间范围、店铺、文件 hash 和批次信息 | 图片、截图、图表文件进入同一 artifact 目录 |
| 字段映射 | 真实导出字段可通过默认别名和人工 `--field-map` 适配；缺字段写 warning | OCR/图表解析字段进入同一映射机制 |
| 入库 | Excel/CSV 可导入 SQLite；重复导入不重复计算；可追溯到来源文件和行号 | 图片解析结果作为结构化行导入 |
| 人工校验 | 字段缺失、未知表、异常数据必须可通过 warning 定位 | OCR 结果必须人工确认后入正式分析 |
| 指标计算 | 订单、退款、商品、评价、人群/转化等有数据则计算，缺数据则明确 warning | 图表提取指标可参与相同计算 |
| 报告 | 单店报告和多店对比报告中的数字来自指标表，不编造缺失数据 | 图片解析带置信度和数据来源说明 |
| AI 分析 | 优先使用聚合指标；建议必须落到店铺、商品、SKU、时间或异常原因 | OCR/图表来源低置信度时要求人工复核 |

## 不做范围

- 不做无人值守自动登录。
- 不绕过验证码、风控或平台权限。
- 不做云端队列、云数据库、多租户权限系统。
- V1 不实现图表解析和 OCR。
- V1 不强制本地脱敏入库；如未来接入外部模型或云存储，需要重新评估。

## 最小闭环

1. 人工准备 5 个店铺的导出 Excel/CSV。
2. 系统按店铺、月份、批次归档原始文件。
3. 系统识别表类型并导入 SQLite。
4. 字段差异能通过 warning 和自定义映射修正。
5. 系统生成单店基础指标和多店对比指标。
6. 报告能指出数据缺口，不用 AI 编造转化、退款或人群结论。
7. 所有报告数字可追溯到指标表和来源文件。

## 测试要求

- Reader/normalizer：CSV、XLSX、多 sheet、空表、中文别名、金额、百分比、日期、缺必填。
- Ingestion：样例文件导入、重复导入幂等、字段映射覆盖。
- Warehouse：临时 SQLite 初始化、任务 metadata 入库、多店数据隔离。
- Metrics：订单周期过滤、退款归因、商品贡献、shop_daily 漏斗口径。
- Collector：配置预检、危险按钮拒绝、文件命名、artifact manifest。
- Reporting/AI：报告快照、payload 结构、缺数据说明。
